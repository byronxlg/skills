# Design work: a positive idea, prototypes, a blind juror

Any UI, page or screen work starts from a design idea, never from a defect list.

- Load the `taste` skill first (app screens: `references/app-screens.md`). Name the screen's one question and its one focal point per state.
- Write 5+ patterns borrowed from named good products in the same domain, each with what it changes on screen. The thing being sold gets a visual identity.
- Build two genuinely different directions as static prototypes with real data; screenshot phone and desktop; look at every shot yourself before anyone else does.
- Judge with a blind juror: a fresh agent sees the before and the candidates unlabelled, against named reference products. Ship the winner only if it beats the before, after fixing the juror's top defects.
- Subtraction is not a design pass: removing boxes, merging text styles or "each fact once" must come with added hierarchy (size and weight contrast, grouping by region, a focal point).
- A screen is done when its screenshots say so, never from tests or code review alone.
- Why: ptt /plan, 2026-11-02. Three subtractive passes left a wall of same-weight grey text and Byron asked which design principle it followed.
